# Orb Sort 3D

A Unity WebGL build served from GitHub Pages as part of
[Little Joy Arcade](https://littlejoyarcade.site).

- **Play:** <https://jd4rider.github.io/orb-sort-3d-web/play/>
- **Cover page:** <https://jd4rider.github.io/orb-sort-3d-web/>

## What is in here

```text
build/WebGL/                the untouched Unity WebGL export (portrait 9:16)
scripts/prepare-site.mjs    turns that export into a Pages-servable site
site/                       generated by the script, not committed
.github/workflows/pages.yml prepare + deploy on every push to main
arcade-manifest.json        the catalogue entry for littlejoyarcade.site
```

There is no bundler, no framework and no dependencies. The only build step is
`prepare-site.mjs`, which needs nothing but Node.

## Why there is a build step at all

The stock Unity template pins a fixed 960 x 600 play area and stretches the
canvas across phones. This game is portrait-first, so `prepare-site.mjs` replaces
that user-agent layout branch with one fit-to-screen rule: it reads the canvas
aspect out of the export (540 x 960), fills the height of the viewport in
portrait, and letterboxes to a centred 9:16 panel in landscape. Any `.br` payload
is expanded and `index.html` pointed at the plain names, because Pages cannot
send `Content-Encoding: br`.

## Updating the game

Re-export from the Unity project, replace `build/WebGL/`, and push:

```bash
rm -rf build/WebGL && cp -R "/path/to/Orb Sort 3D/Builds/WebGL" build/WebGL
node scripts/prepare-site.mjs          # optional: verify locally
git add -A && git commit -m "Ship the newest Orb Sort 3D WebGL export" && git push
```

The workflow re-runs `prepare-site.mjs` and refuses to deploy a payload that
would not load (missing file, or a wasm that does not start with `\0asm`).

## Build settings this export depends on

- **Compression Format: Disabled.** Pages serves files verbatim; a Brotli or
  gzip payload would need a `Content-Encoding` header it cannot set.
- **Canvas 540 x 960** (`PlayerSettings.defaultWebScreenWidth/Height`).
- `PlayerSettings.WebGL.emscriptenArgs` carries the link workaround for a
  Unity 7 alpha toolchain mismatch — see the Unity project's `Tools/WebGL/`.
